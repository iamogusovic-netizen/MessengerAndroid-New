# Messenger v2.10.13 + Android

Единый исходный проект: веб-мессенджер и Android WebView-приложение.

## Состав
- `frontend/` и `backend/` — исходники веб-мессенджера из предоставленного архива v2.10.13.
- `app/` — Android-приложение (WebView, тёмная оболочка, splash screen, иконка M, нативная медиагалерея).
- `.github/workflows/build-apk.yml` — автоматическая сборка APK в GitHub Actions.
- `Dockerfile`, `docker-compose.yml`, `Caddyfile` — серверная конфигурация из исходного архива.

## Сборка APK через GitHub
1. Создайте новый пустой GitHub-репозиторий.
2. Загрузите **содержимое этой папки целиком в корень репозитория**, включая скрытую папку `.github`.
3. Убедитесь, что ветка называется `main`.
4. Откройте Actions → `Build Messenger APK` → Run workflow.
5. После успешной сборки скачайте артефакт `Messenger-v2.10.13-Android-debug`.

## Важное разделение
Android-приложение открывает адрес `http://89.125.121.18`. Оно получает веб-интерфейс с сервера, а не из APK. Поэтому включение обновлённого `frontend/` в этот репозиторий **само по себе не обновляет сайт на сервере**. Для публикации веб-версии нужно отдельно обновить файлы на сервере и перезапустить сервис.

## Сохранность данных
В архив не включены резервные копии и файлы базы данных. Не заменяйте серверную папку `data/` и файл `.env` при публикации обновления. Перед изменениями на сервере создайте резервную копию.

## Ограничения, которые нужно проверить
- GitHub Actions должен завершиться успешно; локальная Android-сборка в этой среде не выполнялась.
- На реальном Android-устройстве нужно проверить запуск, сохранение сессии, разрешения галереи и отправку нескольких файлов.
- Множественная отправка зависит также от поддержки `<input type="file" multiple>` на веб-странице и обработки нескольких файлов её JS/backend.
- Для релиза рекомендуется HTTPS вместо HTTP.
