# Установка мессенджера на VPS по IP, без домена

Эта сборка настроена для подключения по публичному IPv4 без покупки домена. HTTPS обеспечивает Caddy с внутренним (самоподписанным) центром сертификации. Поэтому сертификат нужно вручную добавить в доверенные корневые центры на каждом клиентском Windows-компьютере. Без этого браузер/Electron может показывать ошибку сертификата, а WebCrypto не будет работать как ожидается.

## 1. Что нужно

- VPS с Ubuntu 22.04/24.04 LTS или Debian 12.
- Публичный глобальный IPv4, доступ по SSH.
- Рекомендуется 2 vCPU, 2 GB RAM, 20–40 GB SSD для небольшого теста.
- В панели VPS разреши входящие TCP-порты 22, 80 и 443. Порт 3000 наружу не открывай.
- Не нужен домен. Частный IP вида 192.168.x.x, 10.x.x.x или 172.16–31.x.x не подойдёт для публичного подключения.

## 2. Загрузка файлов

1. Загрузи `messenger_vps_ip_only.zip` на VPS через WinSCP/SFTP в домашнюю папку пользователя.
2. Подключись по SSH и выполни:

```bash
sudo apt-get update
sudo apt-get install -y unzip
unzip -o ~/messenger_vps_ip_only.zip -d ~/
cd ~/messenger-project
sudo bash deploy/install-vps.sh
```

Если входишь не под root, `sudo` нужен. Установщик попросит публичный IPv4 из панели VPS. Он установит Docker, создаст `.env`, проверит конфигурацию и запустит приложение.

## 3. Проверка сервера

На сервере выполни:

```bash
cd ~/messenger-project
sudo docker compose ps
sudo docker compose logs --tail=100
```

Адрес приложения: `https://ТВОЙ_IP/`.
Health endpoint: `https://ТВОЙ_IP/api/health`.

## 4. Доверие HTTPS-сертификату на Windows

Внутренний сертификат не является общедоверенным автоматически. Повтори эти действия на каждом компьютере, где будет запускаться клиент.

1. На VPS выполни:

```bash
cd ~/messenger-project
sudo docker compose exec caddy sh -lc 'find /data -type f -path "*/pki/authorities/local/root.crt" -print'
```

2. Команда покажет путь к `root.crt`. Скопируй ТОЛЬКО этот файл на свой компьютер через WinSCP/SFTP. Обычно путь в контейнере: `/data/caddy/pki/authorities/local/root.crt`. Для копирования можно использовать:

```bash
sudo docker cp "$(sudo docker compose ps -q caddy):/data/caddy/pki/authorities/local/root.crt" ./root.crt
```

Если команда сообщает, что файл не найден, используй путь, который показал `find`, и повтори `docker cp` с ним. Не копируй `root.key`, другие `*.key` или весь каталог `pki`.

3. Перенеси `root.crt` на Windows. Нажми `Win+R`, введи `mmc`, затем **Файл → Добавить/удалить оснастку → Сертификаты → Учётная запись компьютера → Локальный компьютер**. В дереве открой **Доверенные корневые центры сертификации → Сертификаты**, нажми правой кнопкой → **Все задачи → Импорт** и выбери `root.crt`. Проверь, что импортируешь именно корневой сертификат Caddy, полученный с собственного VPS. Для импорта может потребоваться администратор Windows.

4. Полностью закрой и заново открой браузер/настольный клиент. Открой `https://ТВОЙ_IP/api/health`. Ожидается `{"ok":true}` без ошибки сертификата.

**Безопасность:** этот корневой сертификат даёт доверие сертификатам, выпущенным внутренним CA данного VPS. Защищай сам сервер и его хранилище. Никогда не передавай `root.key`. Если сервер скомпрометирован, удали установленное доверие и переустанови сертификаты/CA.

## 5. Подключение настольного приложения

На Windows открой `%APPDATA%` и найди папку данных приложения «Мессенджер» (в зависимости от сборки она может называться иначе). В ней создай файл `server.json` с содержимым, заменив IP на свой:

```json
{
  "serverUrl": "https://ТВОЙ_IP"
}
```

Сохрани файл и перезапусти приложение. Проверь регистрацию, вход, поиск пользователей, обмен сообщениями с двумя клиентами и переподключение после временного отключения сети.

## 6. Команды управления

```bash
cd ~/messenger-project
sudo docker compose ps
sudo docker compose logs -f --tail=100
sudo docker compose restart
sudo docker compose up -d --build
```

Резервная копия базы:

```bash
sudo docker compose exec -T app sh -c 'cat /data/store.json' > ~/messenger-project/backups/store-$(date +%F-%H%M%S).json
```

Храни копии также вне VPS. Не публикуй `.env`, базу, резервные копии или закрытые ключи в открытом доступе.

## Важные ограничения

- Эта сборка использует внутренний TLS-сертификат; доверие нужно настроить отдельно на каждом клиентском устройстве. Это не равно общедоверенному сертификату для публичного сайта.
- Если публичный IP изменится, обнови `SERVER_IP` в `.env`, затем выполни `sudo docker compose up -d --force-recreate caddy` и проверь сертификат/клиентскую конфигурацию.
- JSON-база рассчитана на прототип. Нужны аудит безопасности, ограничения частоты запросов, проверка защиты сессий/WebSocket, тестирование E2EE и регулярные резервные копии до публичного запуска.
- Старые аккаунты с локального ПК автоматически не появятся на VPS. Импорт поддерживает старую серверную базу `backend/data/store.json`, если новая база ещё не создана.
